## Zetaris

### Takeaway

Zetaris is a query-in-place “data harness”: one SQL surface over sources that stay where they are. A 5-day team can run it locally or as a Hobby cluster in their own AWS account (Zetaris fee $0, AWS bill is theirs). The cookbooks judges will already know are PokéAPI, NY Taxi/TPCDS, EDGAR+SIC, and the NOAA GHCN file recipe. PUDL is documented as known-to-fail, so an EDGAR–PUDL–NOAA copy is a bad demo.

### Cited Findings

- Getting-started is written for this hackathon. Two access routes: download a local bundle from Zetaris Cloud’s Run locally page, or a managed AWS cluster created from the participant’s own AWS account. Supplied samples are NY Taxi and TPCDS. First optional dataset is PokéAPI (Pikachu’s abilities). Further sources are under Cookbooks. Demo instructions point at a demo template plus the event page. — [Start here](https://zetaris.github.io/getting-started/)
- The same start page publishes “Open in Cursor”, “Open in Codex”, and “Open in Claude Code” deeplinks. The Cursor prompt is a JDBC readiness check (`scripts/preflight.py --jdbc`, `SELECT 1`, `SHOW LIGHTNING DATABASES`, inspect NY_TAXI and TPCDS_DB, `LIMIT 5`, do not create objects). Credentials stay in `.env.local`. JDBC needs a driver JAR. — [Start here](https://zetaris.github.io/getting-started/)
- Cookbook index (`recipe-readiness`) splits work into REST, file, and USL cookbooks, and a “leave for later” table. PUDL, Foursquare, Overture, Ookla, and GBIF are known registration or query failures. Singapore PM2.5 is known to fail. NASA DONKI still needs connector and format checks. Singapore housing and Open Food Facts bulk downloads are fetchers only. Kafka, SQL databases, logs, and PDFs are “not ready for onboarding.” — [Cookbooks](https://zetaris.github.io/getting-started/docs/guides/recipe-readiness.html)
- REST catalog, registered with `CREATE LIGHTNING REST TABLE`. Verified: SEC EDGAR XBRL company facts; PokéAPI (BSD-3-Clause); Open Food Facts live single-product API (ODbL); NASA NeoWs `/neo/browse` (public domain); Eurostat; Statistics Canada WDS; Australian ABS CPI example (CC-BY 3.0 AU); EDGAR company profiles joined to SIC; company_dns US SIC V3+V4 (Apache 2.0 service); company_dns EU NACE; company_dns Japan industry classification. Unverified: NASA DONKI. Known to fail: Singapore data.gov.sg PM2.5 (HTTP 502 on first create). Deprecated: company_dns V3-only script, replaced by source 12. — [REST source catalog](https://zetaris.github.io/getting-started/open_data/rest_apis/rest-api-sources.html)
- EDGAR access as documented there: free, no authentication, declared `User-Agent`, 10 requests/second. Licence called ambiguous: filings are company-authored; do not bulk-redistribute extracted data. NASA `DEMO_KEY`: 30 requests/hour and 50/day per IP; a free `api.data.gov` key raises this to 1,000/hour; NeoWs and DONKI share the `DEMO_KEY` quota. company_dns defaults cited as 200 requests/minute with burst 20, or 5/minute burst 1 on the strictest tier; a burst over the allowance returns 429. — [REST source catalog](https://zetaris.github.io/getting-started/open_data/rest_apis/rest-api-sources.html)
- File catalog. Verified: NOAA GHCN-Daily CSV at `s3://noaa-ghcn-pds/csv/by_year/2025.csv` (CC0-1.0), with `CACHE TABLE` required because uncached scans were too slow; AWS Public Blockchain Parquet (licence unresolved). Known to fail: PUDL (registration fails because the connector rejects the dotted bucket `pudl.catalyst.coop`; an earlier install record of success is an unresolved contradiction); Foursquare (registers, queries HTTP 500); Overture (bounded samples work, cache and analytical queries fail or hang); Ookla (HTTP 500, and CC BY-NC-SA 4.0 non-commercial); GBIF (queries HTTP 500, aggregate CC-BY-NC). — [File source catalog](https://zetaris.github.io/getting-started/open_data/parquet_csv/parquet-csv-data-sources.html)
- Project-path page tells teams to pick a question, use a cookbook only as a start, and for a multi-source demo to check the join key, duplicates, and missing matches. It points at an EDGAR+SIC USL walkthrough (foreign-key check found one invalid record; materialisation unverified) and an “EDGAR, PUDL and NOAA” advanced walkthrough that it labels blocked: “PUDL is blocked, its weather period is partial, and its data-quality result is unverified.” The PUDL chart example can use sample data for layout, but “a real query is needed to show the connection works” and “is available once PUDL works on your instance.” — [Choose what to build](https://zetaris.github.io/getting-started/docs/guides/project-paths.html)
- Demo template they want filled: the question, a result table/chart/app, what is still unchecked, a source table (link, attribution, what one row means, dates and limitations), setup SQL in order, a saved query plus a small output, how to start the app, and when it was run. Credentials must not be included. Sample-data UI tests must be labeled as such. — [Prepare your demo](https://zetaris.github.io/getting-started/docs/guides/demo-template.html)
- Hobby tier on the product site: $0.00, “Free forever.” Includes core platform with Spark and Presto, declarative Query Director, single node, max 12 vCPUs. “You pay your cloud provider for compute. We charge nothing until you upgrade.” “Live in ~20 minutes · real cluster, your VPC.” Professional is $0.14/vCPU/hour and adds Trino, AI-based Query Director, AI Data Steward, and the unified semantic layer. Enterprise is $0.20/vCPU/hour and adds AgentFlow and GPU scaling. Architecture copy: the platform runs in the customer’s cloud account; Zetaris does not hold a long-lived credential; data is queried in place. — [Zetaris Cloud](https://www.zetaris.com/cloud)
- The managed-AWS hackathon guide is more specific than the marketing card and is the build-risk document. The participant signs into Zetaris Cloud Gateway and an AWS account that can create the CloudFormation stack. Recommended region in that guide is `us-west-1`. AWS bills resources directly, separate from the Zetaris tier. Billable resources can charge from setup completion until deletion, even when no compute cluster is running; suspending a cluster does not remove account setup or retained storage. The guide’s trial size is Mini: two nodes, four vCPUs total, not the marketing “max 12 vCPUs.” Provisioning is about 30 minutes across seven stages. Cluster delete keeps EFS and S3; the participant must delete the CloudFormation stack themselves. Teardown of the cluster is about 15 minutes. — [Managed AWS cluster](https://zetaris.github.io/getting-started/docs/install/managed-aws-cluster-guide.html)
- Local route exists as an alternative to AWS: “For Docker Compose on your own computer, see Install locally,” and the start page points at a Cloud download. Hardware minimums for that Docker install were not on the pages opened here. — [Managed AWS cluster](https://zetaris.github.io/getting-started/docs/install/managed-aws-cluster-guide.html); [Start here](https://zetaris.github.io/getting-started/)
- Cursor is a published connection target. The Cloud page says “Add Zetaris as an JDBC server in Cursor” and its “View connection guide” link goes to the getting-started index, not to a separate Cursor manual. The knowledge-base nav lists a Cursor connection guide at `https://kbase.zetaris.com/knowledge/coding-agent-connection-guide-cursor`. Fetching that URL on 2026-10-20 returned the title and empty search chrome only; the guide body did not render. The Cloud page animation shows MCP-style calls (`zetaris.list_sources`, `zetaris.query`) and a merchant-risk USL with 40 data-quality rules. That animation is product marketing, not a cookbook. — [Zetaris Cloud](https://www.zetaris.com/cloud); [Cursor connection guide URL](https://kbase.zetaris.com/knowledge/coding-agent-connection-guide-cursor)
- Michael Hay, CTO of Zetaris, is a published judge of this hackathon. Zetaris’s 6 Oct 2026 release says Zetaris and SpaceXAI headline the event and that builders pair “SpaceXAI’s Grok Build” with the Zetaris AI Data Harness. Toni Adams is quoted as Head of Global Partnerships, SpaceXAI; she is not on the judge list. Steve Nouri is named as GenAI Works CEO and a new Zetaris AI Strategy Advisor; he is not on the judge list. — [event page](https://hackathon.genai.works/event/open-agent-hackathon-2026); [Zetaris launch release, 6 Oct 2026](https://www.zetaris.com/company/media-and-press/zetaris-launches-cloud-ai-data-harness-for-ai-agents)

### Inferences

- A federated-query demo that is not a cookbook copy needs a live join the repo does not already walk through: two or more verified sources (for example NOAA GHCN plus a verified REST source such as EDGAR, Eurostat, or ABS), a join key that is not “company name,” a result row a person can check against the source, and an explicit note of misses and date gaps. Replaying PokéAPI, NY Taxi `LIMIT 5`, or the EDGAR+SIC USL script is the path their own docs already teach every team.
- Do not build the demo on PUDL. Their own project page says that walkthrough is blocked. Using the PUDL chart with sample data and calling it a live federated query contradicts their demo template.
- Hobby is not “free compute.” It is a free Zetaris software tier on a cluster the team pays AWS for, and the hackathon Quickstart can leave EFS/S3 charges after the cluster is deleted. The local Docker route is the way to avoid an AWS bill, if the download and machine are ready before 22 Oct.
- The marketing Hobby shape (single node, up to 12 vCPUs) and the hackathon Mini shape (2 nodes, 4 vCPUs) are both published. A team should not assume the $0 card’s 12 vCPU cap is what the Quickstart form will launch.

### Gaps

- The Cursor knowledge-base article body did not render, so the exact Cursor clicks (JDBC vs MCP, tool names, auth fields) are not verified beyond the getting-started deeplink and the Cloud marketing sentence.
- Local Docker CPU/RAM/disk minimums were not on a page opened here.
- No Zetaris page opened here states a hackathon-only credit, a waived AWS bill, or a shared cluster. The AWS guide says the opposite: the participant’s AWS account is billed.
- Whether Michael Hay scores Zetaris usage inside the 10-point sponsor-tech category, or only the track prizes, is not stated.

## Bright Data

### Takeaway

The product a team can wire in five days is the Bright Data MCP server: search, page unlock/scrape, pre-built scrapers, and a scraping browser. The published free tier is 5,000 shared credits per month per account, no credit card, not a hackathon grant. Their own unlocker copy says it unlocks public pages and anti-bot challenges; it does not name a site that returns 403, and this note does not either.

### Cited Findings

- MCP overview: agents get real-time public web data through MCP, on the Web Unlocker API, with proxy rotation, anti-bot challenges, and CAPTCHA solving. Two run modes: remote hosted, or local self-hosted. “Every new account includes 5,000 free requests per month.” Tool groups can be limited, for example `groups=scrapers,browser` or `tools=run_scraper`. The same note says the MCP free tier is the account-level free tier of 5,000 credits per month from one shared pool, shared across users on a team account, because MCP runs on Web Unlocker. — [MCP server overview](https://docs.brightdata.com/ai/mcp-server)
- That overview links Claude, Cursor, and other MCP clients, plus a tools page, FAQs, usage examples, and the GitHub server. A card offers a general Startup Program of “fully funded access … (up to $20K value).” The card does not say Open Agent Hackathon participants are enrolled. — [MCP server overview](https://docs.brightdata.com/ai/mcp-server)
- Tools page: 32 tools, all on by default. Search and unlock/scrape: `search_engine` (Google, Bing, or Yandex; JSON for Google, Markdown for Bing/Yandex); `search_engine_batch` (up to 10 queries); `discover` (intent-ranked results with title, description, URL, relevance score); `scrape_as_markdown` and `scrape_as_html` (unlocker, bot protection and CAPTCHA); `scrape_batch` (up to 10 pages); `extract` (Markdown then AI sampling to JSON). Scraper API: `search_scrapers`, `get_scraper_details`, `run_scraper` (waits up to 45 seconds, otherwise returns `snapshot_id` with status `running`; billed per record), `get_scraper_progress`, `get_scraper_results`, `refresh_scrapers`. The page says there are “thousands” of pre-built scrapers. Dataset search, no snapshot step, up to 10 records per call: only three datasets are listed as searchable — LinkedIn people profiles, LinkedIn people profiles (contact-enriched), and LinkedIn company information. Browser group: navigate, back, forward, ARIA snapshot, click/type/fill by ref, screenshot, network requests, wait, get text, get HTML, scroll. Separate `geo` tools call ChatGPT and Perplexity. Examples used for `search_scrapers` are the phrases “amazon reviews” and “linkedin.com”, not a claim that those sites block other clients. — [Bright Data MCP tools](https://docs.brightdata.com/products/mcp-server/tools)
- Free-tier page: 5,000 credits per month, about a $7.50 value, no credit card, no promo code. Eligible products: Web Unlocker, SERP API, Web Scraper API (one credit per request or record), Scraper Studio (one credit per page load), Browser API (5 credits per MB, so the full allowance is nearly 1 GB). Unused credits do not roll over; they reset on the first of the month. No deposited funds means a hard stop, not a surprise bill. Unfunded accounts are rate-limited to 1,000 requests per minute across SERP, Web Unlocker, and Proxy products. Proxy products are not in the monthly free credits; new accounts get a separate one-time $2 proxy trial for 7 days. Adding a card is described as verification and is not itself a charge. Pre-commit plans stop the recurring free credits. — [Free tier](https://docs.brightdata.com/general/account/billing-and-pricing/free-tier)
- Web Unlocker marketing: “unlocks any public web page” in one call, stated 98% success rate, proxy rotation, fingerprints, CAPTCHA, retries, pay only for successful requests. Use-case copy is “Scraping any website, including sites with advanced anti-bot protection” and geo-restricted content. It does not list consumer sites as specifically unblocked. It does say social-network account management is not supported, naming Facebook, TikTok, Instagram, X, LinkedIn, YouTube, Reddit, Pinterest, Snapchat, and Discord. Unlocker is not for scripted browser actions; those go to the Browser API. Endpoint shown: `POST https://api.brightdata.com/request` with a zone and bearer key. — [Web Unlocker API overview](https://docs.brightdata.com/scraping-automation/web-unlocker/introduction)
- No Bright Data person appears on the hackathon judge list, and the rendered sponsor-logo strip on the event page did not include Bright Data. — [event page](https://hackathon.genai.works/event/open-agent-hackathon-2026)

### Inferences

- A checkbox integration is one `search_engine` or `scrape_as_markdown` call whose result is not required for the decision. A load-bearing one is an agent step that fails closed when the live page is missing: `discover` or SERP to find the page, unlock/scrape or a pre-built scraper for structured records, and the browser tools only when the page needs a click, scroll, or form. The docs themselves say to turn off unused tool groups so the MCP context stays small.
- Credit math is the build risk. A markdown scrape is cheap (one credit). `run_scraper` bills every record. Browser traffic at 5 credits/MB can exhaust 5,000 credits long before 5,000 page views. A team that shares one account shares one pool. Credits reset 1 Nov, after the 27 Oct deadline, so October’s remaining balance is all they get during the build.
- There is no published evidence in the pages opened that this hackathon hands out extra Bright Data credit. The $20K startup card is a separate program with an application, not an automatic grant.

### Gaps

- No page opened here is a Bright Data hackathon brief, judge quote, or bonus-prize rule for Open Agent Hackathon 2026. Organizer materials outside the live event page were not opened, so Bright Data’s sponsor status is not confirmed on the event page itself.
- No primary page opened here shows a named site returning HTTP 403 to a normal client, or a before/after unblock of a named domain. Do not treat the generic “any website” sentence as a site list.
- Account-approval time, zone-creation steps, and whether LinkedIn dataset search is inside the free credit pool or a paid dataset product were not stated on the pages read. `search_dataset` is documented as a Marketplace Dataset API call; billing for those three datasets specifically was not spelled out beyond the general scraper/free-tier rules.

## Meterless

### Takeaway

Meterless is an open-source local-first agent stack: H-MEM (memory on disk), World Model (shared state), Markovian (chunked long tasks), and Scout Intent (classify and route). The agentathon starter is a retrieval-only, no-API-key notebook over H-MEM. Their own guide weights “Meterless engine usage” at 25%, but that is not the event page rubric, and their guide still says 15–20 October.

### Cited Findings

- Engines page, in the section that defines them in plain language: Markovian is “Long-running tasks without runaway context growth.” H-MEM is “Memory that survives between sessions: working, episodic, and semantic tiers as grep-able files on disk.” World models are “Agents that share the same state, so parallel work stays consistent.” Scout is “Less prompting, better tool selection. Classifies what you’re doing and routes tools accordingly.” The stack is public at `github.com/Meterless/Meterless`. A 90-second demo they tell people to run first is `npx tsx examples/memory-compounding-research/index.ts`, and that prompt says no API keys. — [Engines](https://meterless.ai/engines.html)
- The same page’s hackathon prompt still says “Open Agent Hackathon (Oct 15 to 20, 2026)” and points at `docs/community/hackathon-guide.md` and `templates/agentathon-starter/README.md`. Another prompt says the starter is `npx degit meterless/meterless/templates/agentathon-starter my-agent`, and “Keep the H-MEM memory wiring intact.” A provider prompt documents Runtime 1.4: base URL `http://127.0.0.1:8088/v1`, bearer token from the runtime (placeholder `rt-local` rejected), model ids as routing modes `meterless/<disposition>` (`auto`, `fast`, `deep`, `cheap`, `local`, `fusion`) rather than model names, and a 180 second timeout “because a model load can take minutes.” — [Engines](https://meterless.ai/engines.html)
- Hackathon guide (repo): “Meterless hosts hackathons through GenAI.Works.” It links the official event URL but the table says dates October 15 to 20, 2026. Tracks it lists are its own seven: Memory Agents, Desktop Agents, Creative Swarms, Overnight Agents, Unmetered Apps, Enterprise Workflow Agents, Offline and Local AI Agents. Those names are not the four tracks on the event page. Its judging table is Usefulness 30%, Meterless engine usage 25%, Local-first and privacy design 15%, Quality of demo 15%, Creativity 10%, Documentation 5%. It says the starter README “maps every command to the engine service behind it, which is what the 25% engine-usage rubric line looks for.” — [hackathon-guide.md](https://raw.githubusercontent.com/Meterless/Meterless/main/docs/community/hackathon-guide.md)
- Agentathon starter README title: “The Research Notebook Agent.” “A CLI agent whose memory is real H-MEM… Zero API keys.” Required `npm run setup` vendors H-MEM into gitignored `vendor/`. Commands: `seed`, `ask`, `remember`, `audit`, `sleep --preview`. Persistence is gitignored `.notebook/`. “Where the engine is used (judges look here)” repeats the 25% weight and maps `remember` to MemoryMiningService plus MemoryStoreService, `ask` to MemoryRetrievalService, `audit` to TrustLedgerService, and `sleep` to SleepCycleService. “The default answer mode is retrieval-only and fully offline.” An optional path installs `@anthropic-ai/sdk` and sets `ANTHROPIC_API_KEY`; both modes are labeled in the output. — [agentathon-starter README](https://raw.githubusercontent.com/Meterless/Meterless/main/templates/agentathon-starter/README.md)
- Model library lists, among many others: “Nemotron 3.5 Lightning”, NVIDIA, Balanced, text, local or cloud; “Nemotron 3 Nano 30B-A3B”, NVIDIA, Frontier, text, runs locally; “Nemotron 3 Super”, NVIDIA, Frontier, text, cloud; “Nemotron 3 Ultra”, NVIDIA, Frontier, text, cloud. It also lists “Grok Build 0.1”, xAI, Balanced, text and code, cloud. These are catalog labels, not NVIDIA hardware requirements. — [Model library](https://meterless.ai/models.html)
- DGX Spark is a Meterless Nightshift target, separate from the hackathon prize. The engines page prints `curl -fsSL https://meterless.ai/Nightshift/DGX/install.sh | sh` and an arm64 AppImage. The model-library page, opened the same day, says “Nightshift for DGX. The download link isn’t live yet.” A 3D prompt on the engines page says photo-to-3D needs “a runtime with a seated 3D lane (today, a DGX Spark with the media studio installed).” — [Engines](https://meterless.ai/engines.html); [Model library](https://meterless.ai/models.html)
- No Meterless employee is on the published judge list. The Wildcard track requires Meterless and Zetaris together. — [event page](https://hackathon.genai.works/event/open-agent-hackathon-2026)

### Inferences

- The starter is retrieval-only by default. Shipping the unmodified CLI (`remember` / `ask` / `audit` / `sleep --preview` on seed text) is the example their README tells judges to look for, so it is the obvious checkbox. A load-bearing use keeps those named services but makes memory change a later action: a second session recalls a constraint and picks a different tool, or a long task takes fewer Markovian chunks on the second run, which is the “done” condition in their own engines-page prompts.
- Do not cite 25% as the hackathon score. The event page’s sponsor-tech weight is 10 points, inside a different rubric. Meterless’s 25% is real as their published guide, and it disagrees with the organizer page on both weights and dates.
- Engine code is free and local. A paid or keyed model is optional. The risk is time: `npm run setup`, conformance suites, and a runtime whose first model load they say can take minutes. A DGX Spark is not required to use H-MEM.

### Gaps

- Whether organizers told judges to apply Meterless’s 25% line, or only the event-page 10-point sponsor-tech line, is not on the event page. The rules section bodies (“What you can use”, “Submission requirements”, “Judging”) did not expand in the fetched HTML.
- The DGX Nightshift download is in contradiction across two Meterless pages opened the same day. Availability was not re-checked by running the installer.
- No Meterless page opened here says a DGX Spark is a prize of Open Agent Hackathon 2026. The event page assigns that prize to best use of NVIDIA Nemotron.

## NVIDIA

### Takeaway

As of the 15 Oct 2026 NVIDIA post, the current Nemotron line they are shipping for agents is Nemotron 3.5 Super VL (120B, 12B active), Nemotron 3.5 Bolt 74B-A9B in a 24GB build, with Bolt E4B 4GB due 23 Oct, plus earlier Lightning and Ultra. Super VL NVFP4 and Bolt 24GB are both OpenMDW-1.1. Neither fits a typical laptop; the published small deployment is one DGX Spark or a 24GB-class GPU. This hackathon’s only published NVIDIA award is one DGX Spark Founder's Edition for best use of Nemotron. No participant GPU credit was found.

### Cited Findings

- 15 Oct 2026 NVIDIA blog: Nemotron 3.5 Super VL is an open 120-billion-parameter model for always-on agents. With it: Nemotron 3.5 Bolt 74B-A9B 24GB for local agentic workloads, and Nemotron 3.5 Bolt E4B 4GB “coming Oct. 23.” Super VL and Bolt 74B-A9B “are available now.” They “join the Nemotron family alongside Lightning and Ultra.” “Lightning, released in August, handles high-throughput workloads; Ultra handles the hardest reasoning tasks; and Bolt brings intelligence to the edge.” Super VL “ships with open weights, open datasets and training recipes.” The blog does not name the license identifier. Super VL “runs across NVIDIA’s full hardware stack: on DGX Spark, DGX Station, RTX PRO and RTX systems … on NVIDIA Jetson … and across data center and cloud.” Bolt 74B-A9B 24GB “is designed to run everyday agentic tasks locally on NVIDIA RTX/DGX Spark, using a native 2-bit quantization to fit in 24GB of memory.” Serving stacks named for Bolt: llama.cpp, Ollama, LM Studio, Unsloth, and vLLM. NIM is described as a production microservice. — [NVIDIA blog, 15 Oct 2026](https://blogs.nvidia.com/blog/nemotron-3-5-super-vl/)
- Super VL NVFP4 model card, Hugging Face release date 10/15/2026: 120B total, 12B active, context up to 1M tokens, inputs text/image/video, output text, license OpenMDW-1.1, “ready for commercial or non-commercial use.” Deployment row: “1× DGX Spark, 1× H200, 2× H100, or 1× GB200.” The DGX Spark vLLM quick start is “intended for DGX Spark (GB10) only” and serves one concurrent sequence. Software integration: vLLM, SGLang, TensorRT-LLM; hardware NVIDIA Blackwell and Hopper; OS Linux. A local-hardware section also points at llama.cpp and Unsloth for DGX Spark, RTX Spark, and RTX Pro 6000. If the model requires authentication, set `HF_TOKEN`. NIM and Dynamo are linked as production paths, not as free hackathon credits. — [Super VL NVFP4 model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-NVFP4)
- Bolt 74B-A9B 24GB model card, Hugging Face 10/15/2026: vision-language, 74B total / 9B active, IQ2, context up to 256K, license OpenMDW-1.1, commercial or non-commercial. Summary deployment line: “24GB packed model; vLLM on NVIDIA Ampere (A100), Hopper (H100-80GB), or Blackwell.” Software-integration line on the same card: “Supported Hardware Microarchitecture Compatibility: NVIDIA Blackwell SM120 & SM121” and “Supported Operating System(s): Linux.” Those two hardware lines are both on the card and are not identical. Parent is Nemotron 3.5 Super VL. A benchmark column names “Nemotron 3.5 Lightning 30B-A3B-BF16” but does not document how to serve Lightning. — [Bolt 24GB model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB)

## Across sponsors: checkbox versus load-bearing

### Takeaway

The organizer page scores sponsor tech at 10 points and asks for meaningful use that addresses the problem, not a prototype that mentions a logo. Each sponsor’s own docs describe a good agent as one that does a real job on live data, with memory or evidence the user can check. The checkbox failure mode is running their tutorial and stopping.

### Cited Findings

- Organizer: “focus on building practical solutions rather than simple prototypes or demonstrations.” “Teams are encouraged to make meaningful use of the available sponsor technologies and clearly demonstrate how these technologies contribute to their solution.” Sponsor tech is 10 of 100 points. Impact is 30: a meaningful problem for intended users. Wildcard entries “must integrate Zetaris and Meterless” and “are scored on the new work rather than prior development.” — [event page](https://hackathon.genai.works/event/open-agent-hackathon-2026)
- Zetaris’s own “good demo” is a question, a real result, row-level meaning, limitations, and SQL someone else can rerun. Their project page says company names often are not enough to join records, and says to save duplicates, missing matches, and date gaps. The Cloud page’s pitch is governed query-in-place, “nothing copied,” agents reading a semantic layer rather than raw tables. — [Prepare your demo](https://zetaris.github.io/getting-started/docs/guides/demo-template.html); [Choose what to build](https://zetaris.github.io/getting-started/docs/guides/project-paths.html); [Zetaris Cloud](https://www.zetaris.com/cloud)
- Bright Data’s own “good agent” sentence is an MCP client that can search, scrape, and read live public pages without the team running a data pipeline, with unlocker handling anti-bot on the MCP path. They tell clients to enable only the tool groups the agent will call. — [MCP server overview](https://docs.brightdata.com/ai/mcp-server); [MCP tools](https://docs.brightdata.com/products/mcp-server/tools)
- Meterless’s own “good agent” is engines that are actually invoked: the starter README says judges look at the named H-MEM services, and the engines page’s done-conditions are a conformance suite plus a visible behavior change (second run uses fewer chunks; memory changes the plan; injection eval hits their thresholds). Local-first is a named goal in their guide. — [agentathon-starter README](https://raw.githubusercontent.com/Meterless/Meterless/main/templates/agentathon-starter/README.md); [Engines](https://meterless.ai/engines.html); [hackathon-guide.md](https://raw.githubusercontent.com/Meterless/Meterless/main/docs/community/hackathon-guide.md)
- NVIDIA’s 15 Oct post describes a good agent as specialized, tool-using, and able to stay on infrastructure the builder controls, with Super VL aimed at “instruction following, tool use, multistep business workflows, and visual understanding.” The hackathon prize is “best use,” not “mentioned Nemotron.” — [NVIDIA blog](https://blogs.nvidia.com/blog/nemotron-3-5-super-vl/); [event page](https://hackathon.genai.works/event/open-agent-hackathon-2026)
- Zetaris’s release describes the intended pairing as a coding harness plus a data harness, not either one alone. — [Zetaris launch release](https://www.zetaris.com/company/media-and-press/zetaris-launches-cloud-ai-data-harness-for-ai-agents)

### Inferences

- Checkbox patterns judges can already recognize: Zetaris PokéAPI or `SELECT * FROM NY_TAXI.taxi_zones LIMIT 5`; the EDGAR+SIC USL script; the EDGAR–PUDL–NOAA guide while PUDL is still broken; Meterless `notebook.ts ask` on the seed sentence with no product around it; a Bright Data `search_engine` call pasted into a chat answer; a README badge that says Nemotron or Cursor while the demo runs a different model.
- Load-bearing pattern that matches the written rubrics: one user and one decision. Zetaris runs a federated query the cookbooks do not ship, and the answer cites those rows. Bright Data fetches a page or structured record the decision depends on, inside the free-credit budget. Meterless memory or Scout routing changes the next action across two runs, through the named services. Nemotron, if used, is the model that does that reasoning or tool call, on hardware the team can actually show. Cursor or Grok Build, if used for the Cursor prize, is the harness that produced the project, not a deeplink opened once.
- Do not stack all five sponsors to chase the 10-point line. The event text says “effectively,” and Wildcard only requires Zetaris and Meterless. Extra logos that never affect the result fight the Impact and Demo points, which together are 45.

### Gaps

- Official rules text for allowed tools, repo visibility, video length, and whether sponsor use is mandatory on tracks 1–3 did not render. The visible about text says “encouraged,” while Wildcard says “must.”
- No judge quote from NVIDIA, Bright Data, or Meterless was found on a page opened for this note. Hay and Armentano are the only sponsor-side judges published.
