# REST public-health operations idea for Open Agent Hackathon 2026

Checked 2026-10-20. Scope is US public-health and safety operations whose official data is REST or CSV. Drug-shortage substitution was not reconsidered. Hospital price transparency and prior authorization were not opened. A Davis-Bacon packet was not revived. Bright Data is not used. One idea survives. Two directions are rejected on pages opened this session.

## Does one idea survive the source, join, and 27 October open-case tests?

### Takeaway

Yes. The survivor is a one-page draft Recall Response attestation for FDA device recall Z-3151-2026, for the customer who signs the form the firm already told customers to return. The draft is filled only from two live JSON sources joined on recall number Z-3151-2026 and event id 99758. Status is taken from the CDRH recall record, which FDA’s own recall page still showed as “Open, Classified” with a page update of 10/19/2026. The openFDA enforcement “Ongoing” flag is not used as proof the recall is still open.

### Inferences

- The demo record has no deadline of 22 October 2026. On the FDA page last updated 10/19/2026 the status is still “Open, Classified,” and footnote 3 says not all products have been corrected or removed. Initiation was 2026-08-10, so 27 October 2026 is day 78. In GAO’s FY2020–FY2024 set, the shortest terminated Class I recall still took 162 days from initiation to termination. A termination before 27 October would be faster than every terminated Class I recall in that set. That is evidence, not a guarantee. The demo re-queries `device/recall` for Z-3151-2026 and stops if `recall_status` is no longer Open, Classified.
- The join key is an identifier, not a name. `device/recall.product_res_number` equals `device/enforcement.recall_number` (Z-3151-2026). `device/recall.res_event_number` equals `device/enforcement.event_id` (99758). FEI 1047429 and product code OGD are on the recall record and the FDA HTML page. They were not printed on the enforcement object that was retrieved (`openfda` was empty there).
- Enforcement `status=Ongoing` is the wrong field for “still open.” The enforcement docs say that status is not updated after classification. The draft prints status only from the CDRH recall record / FDA HTML page.
- The two openFDA files are not SEC EDGAR, PUDL, NOAA GHCN, PokéAPI, or NY Taxi, and neither source is a PDF. Zetaris registers them as REST JSON tables. Meterless is memory only: no local Nemotron. Bright Data is not in the path.
- The manufacturer’s attached form is not in the JSON. The draft quotes the six action lines and leaves quantity, signature, and date blank. It does not send anything to AVID, a distributor, or FDA.

### Gaps

- Rules section 05 on the event page did not expand in this fetch, so this note does not re-quote a “must use Cursor” sentence from the live page. The build still uses Cursor because that is a constraint of this assignment.
- The H-MEM README was not re-fetched this session. The required behavior is local memory of one user decision that changes the next packet. The implementation target is the Meterless agentathon starter’s remember/ask path, not a new memory design and not a local NVIDIA model.
- MAUDE field names were not confirmed. Both attempted queries 404’d, so an injury count must not appear.
- No page opened here says a specific job title must sign the customer form. The FDA action addresses “customers (end-users)” and “distributors.” The signature block names the role the facility writes in. It does not invent “Clinical Engineering Director” as a legal requirement.
- Whether Z-3151-2026 is still Open, Classified on 27 October 2026 cannot be known on 20 October. The stop-if-status-changed rule is the control.

## What is the artifact, the demand figure, who already does the nearby job, and what will not be built in five days?

### Takeaway

The artifact is a draft the customer signs, not a chatbot and not a recall inbox. Every factual line cites the Z-3151-2026 recall row or the matching enforcement row. Demand is GAO’s count of device recalls FDA oversaw, not a guessed labor rate. NotiSphere already stores electronic recall responses for hospitals whose suppliers push notices. This draft does not do that job. It is one public-record form for one open Z-number, and a stored “not on hand” decision removes the quarantine steps on the second run.

### Cited Findings

- The form the draft supports is named in the recall row, not invented: “Complete the attached Recall Response Form and return.” Steps the draft may quote, because they are in that same action string, are quarantine of the listed kits, warning labels, discard of the sodium chloride 0.9% USP 10 mL flush ampules before use, and distributor notification. Quoting those steps is not a dose and not a clinical decision. The signer decides what was found. — [FDA recall page](https://www.accessdata.fda.gov/scripts/cdrh/cfdocs/cfres/res.cfm?id=222418); [recall JSON](https://api.fda.gov/device/recall.json?search=product_res_number:%22Z-3151-2026%22&limit=1)
- Demand, primary page, opened: from FY2020 through FY2024, FDA oversaw 3,934 medical device recalls, about 900 initiated in each of those five years, of which 2,433 (62 percent) were still ongoing at the time of GAO’s analysis. Population is medical device recalls in FDA’s Recall Enterprise System initiated in that window. Report date December 8, 2025. Data end September 30, 2024. Class I terminations in that set took a minimum of 162 days. A separate live volume, not an annual rate: 14,366 device-recall rows had `recall_status` Open, Classified in the openFDA extract `last_updated` 2026-10-15, out of 59,494 recall rows. — [GAO-26-107619](https://files.gao.gov/reports/GAO-26-107619/index.html); [openFDA status count](https://api.fda.gov/device/recall.json?count=recall_status)
- Official tool 1, FDA recall database. Job it does: shows one classified recall, including status, lots, UDI-DI, FEI, and the firm’s action text. Job it does not do: a signable customer response, a join to the enforcement report, or a second version that drops steps because of a stored facility decision. — [FDA recall page](https://www.accessdata.fda.gov/scripts/cdrh/cfdocs/cfres/res.cfm?id=222418)
- Official tool 2, openFDA device recall API. Job it does: weekly JSON of the classified-recall database, including a `recall_status` that, on the call made here, already contains tens of thousands of Terminated rows. Job it does not do: the response form. Its own page says not to use the feed to issue public alerts. — [openFDA device recall](https://open.fda.gov/apis/device/recall/)
- Official tool 3, openFDA device enforcement API. Job it does: weekly RES JSON, including classification, report date, and the same recall number. Job it does not do: lifecycle tracking. The docs say status is not updated after the enforcement report is published. — [openFDA device enforcement](https://open.fda.gov/apis/device/enforcement/)
- Commercial tool, NotiSphere’s hospital page, opened 2026-10-20. Job it does: supplier-pushed alerts “only to providers affected by the recall,” acknowledgement, “send electronic responses,” task delegation, and an audit trail of notifications and responses. A quoted user on that page, Bob Cuthbertson, Director of Materials Management, says “only 2.5% of the alerts we receive actually apply to us.” That 2.5% is one person’s statement on the vendor page, not a national rate. Job the page does not claim: building the response from the public FDA JSON when the supplier has not sent a NotiSphere notice, or reconciling enforcement status against CDRH status. — [NotiSphere for providers](https://www.notisphere.com/providers)
- ECRI’s former alerts URL redirected to `https://staritas.com/recall-management/`, and the supply-chain URL redirected to `https://staritas.com/supply-chain-intelligence/`. Both Staritas pages returned a heading and no product description, so ECRI’s feature list is not used. — [Staritas recall page](https://staritas.com/recall-management/); [Staritas supply-chain page](https://staritas.com/supply-chain-intelligence/)
- Memory behavior that changes the second packet, without a model: run 1 has no stored decision and prints the six cited action steps plus blank quantity lines for lots 1641713, 1641714, 1659697, and 1668209. The user stores one local decision: kit DPGE002-02, UDI-DI 10809160410325, is not in this facility’s inventory, so quarantine, relabel, and ampule-discard steps must not be included. Run 2 prints a not-on-hand attestation that still cites Z-3151-2026, event 99758, FEI 1047429, status Open, Classified, the four kit lots, ampule lot AB4003, and distribution IL, NC, VA, WY, and it omits those three steps. The signer still signs. The software does not decide the kit is absent unless that decision is the stored memory.

### Inferences

- This is not NotiSphere. NotiSphere’s opened page is a supplier-to-hospital messaging and response store. Shipping a recall inbox, an inventory match, or electronic delivery to AVID would be that product, and the idea would then fail. The five-day artifact is one cited draft for one Z-number.
- Track fit is the evidence track, not a chatbot. The explanation a judge can check is why enforcement “Ongoing” is ignored and CDRH “Open, Classified” is printed, with both rows on screen.
- GAO’s “about 900” a year is the demand figure to say out loud. Do not add it to the 14,366 open-classified stock. Do not say 14,291 enforcement “Ongoing” rows are open recalls. The enforcement docs forbid that reading.
- Five days will build: two Zetaris REST tables (`device/recall`, `device/enforcement`) joined on the Z-number, a check that event ids match, one draft for Z-3151-2026, the openFDA medical-care disclaimer and the enforcement lifecycle disclaimer on the face of the draft, a signature and date line, and one H-MEM decision that changes run 2. Development in Cursor.
- Five days will not build: email or API submission to AVID, distributors, or FDA; label printing; an inventory system; a scan of all 14,366 open-classified rows; MAUDE matching; effectiveness percentages; a public alert; local Nemotron or any other local GPU model; Bright Data; a clinical instruction beyond the firm’s own cited discard line; multi-facility rollups; the manufacturer’s missing PDF attachment.

### Gaps

- No opened page gives hours or dollars spent by hospitals on device-recall paperwork in 2023–2026. GAO’s recall counts and the 162-day Class I minimum are the quantified primary figures. The NotiSphere 2.5% sentence is not a substitute.
- ECRI/Staritas product copy did not render, so it is not claimed as a competitor and not claimed as absent.
- The Meterless starter’s exact command names were not re-read this session.
- openFDA’s recall docs page and the FDA HTML footnote disagree about whether status is frozen. The draft follows the HTML footnote and the live `recall_status` value, and it says so.

## Which two directions were rejected, and what page killed each?

### Takeaway

A nursing-home Plan of Correction was killed by the CMS health-citations CSV: the description column is the generic tag sentence, not the surveyor’s finding. A drinking-water public notice was killed by the EPA rows for the same water system: the current ECHO flag and the only violation JSON returned are different violations years apart, so a notice would invent the violation.

### Cited Findings

- CMS Health Deficiencies, dataset `r5ix-sfxw`, metastore opened 2026-10-20. Description: citations in the last three years with tag, description, scope and severity, citation status, and correction date, one citation per row. `modified` 2026-09-30, `released` 2026-10-08, `nextUpdateDate` 2026-10-28. CSV URL returned by that metastore: `NH_HealthCitations_Sep2026_2.csv`. A range read of the file returned the header and data rows. Columns include CMS Certification Number (CCN), Survey Date, Deficiency Tag Number, Deficiency Description, Scope Severity Code, Deficiency Corrected, Correction Date, and Processing Date. Processing Date on the rows read was 2026-09-01. The description values read are the standard tag sentences, for example tag 0656, “Develop and implement a complete care plan that meets all the resident's needs, with timetables and actions that can be measured,” and tag 0880, “Provide and implement an infection prevention and control program.” They are not a facility-specific deficient-practice narrative. Rows read already had correction dates in the past, including CCN 015015, survey date 2026-02-20, correction date 2026-03-31, status “Deficient, Provider has date of correction.” The file is ordered by CCN. This read did not scan every row for a blank correction date. — [CMS metastore item r5ix-sfxw](https://data.cms.gov/provider-data/api/1/metastore/schemas/dataset/items/r5ix-sfxw); [Sep 2026 citations CSV](https://data.cms.gov/provider-data/sites/default/files/resources/e7cd6855ef21902a6803f11dfa287fad_1790792147/NH_HealthCitations_Sep2026_2.csv)

### Inferences

- The CMS CSV is a legal source for Zetaris: it is CSV, and CCN is a facility id, which would have satisfied the join rule against staffing or penalties. It still cannot support a Plan of Correction a nursing-home administrator could sign. A POC has to answer the surveyor’s finding. The column that was read states the regulation in generic words. Using it as the finding would put words on the signature page that the row does not say. The next CMS refresh is dated 2026-10-28, the day after submission, but that does not repair the missing narrative. This is the page that killed the nursing-home draft: the citations CSV, reached through the metastore record.
- The drinking-water draft dies for the same reason the Davis-Bacon packet died in spirit: the core fact is not in a row the demo can show. ECHO says OH3800112 is a current serious violator for two named rules and does not give a violation id. Envirofacts gives a violation id for a 2016–2017 TTHM monitoring violation at that same PWSID. A Tier 2 notice needs the violation, the contaminant, the period, and the tier. Filling those in from the ECHO flag would be a guess. No public-notice product comparison was required once the rows failed. The pages that killed it are the ECHO system result and the Envirofacts JSON for OH3800112.
- A third source was probed and not selected, not used as one of the two kills. openFDA food enforcement returned HTTP 200, `last_updated` 2026-10-07, and 113 Ongoing rows with `report_date` from 20260901 to 20261020. One of them is H-1339-2026, Everything Sprouts, Class I, report date 20260923, lots 222, 223, 226, and 230. `openfda` on that object was empty, so there was no FEI or other identifier to a second confirmed file. The enforcement status disclaimer would also block treating “Ongoing” as still open on 27 October. — [food enforcement sample](https://api.fda.gov/food/enforcement.json?search=report_date:[20260901+TO+20261020]+AND+status:Ongoing&limit=1)

### Gaps

- The CMS citations file was not fully scanned, so this note does not say how many citations have a blank correction date. The generic description column is enough to reject the POC either way.
- No current SDWA violation-id extract, other than the stale Envirofacts rows, was downloaded. A quarterly ECHO CSV might contain a current violation id. It was not opened, so the public-notice idea is not ready. It is not a hidden survivor.
- OSHA’s severe-injury dashboard was requested in the same run as the CMS range read. The returned output was truncated before any OSHA date line, and a search of that log did not find the page text. OSHA is neither accepted nor rejected here.
- No state drinking-water notice generator and no iQIES Plan of Correction screen were opened. They were unnecessary after the row-level failures above.
